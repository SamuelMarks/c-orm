# cdd-c SQL DDL Support

The `cdd-c` parser strictly supports a specific subset of SQL DDL for generating C structs and metadata. This ensures predictable memory layouts and consistent code generation across supported databases.

## Supported Data Types

The following SQL data types are fully parsed and mapped to `c-orm` C types:

* **Small/Standard Integers**: `SMALLINT`, `INT`, `INTEGER` -> `int32_t` (`C_ORM_TYPE_INT32`)
* **Big Integers**: `BIGINT` -> `int64_t` (`C_ORM_TYPE_INT64`)
* **Floating Point**: `FLOAT` -> `float` (`C_ORM_TYPE_FLOAT`), `DOUBLE` -> `double` (`C_ORM_TYPE_DOUBLE`)
* **Exact Fixed-Point Decimals**: `DECIMAL(p, s)`, `NUMERIC(p, s)` -> `c_orm_decimal_t` (`C_ORM_TYPE_DECIMAL`, preserving exact `precision` and `scale` up to 38 digits)
* **Decimal Floating Point (Db2)**: `DECFLOAT(16)`, `DECFLOAT(34)` -> `c_orm_decimal_t` (`C_ORM_TYPE_DECFLOAT`)
* **Booleans**: `BOOL`, `BOOLEAN` -> `bool` (`C_ORM_TYPE_BOOL`)
* **Strings & CLOBs**: `VARCHAR(n)`, `TEXT`, `CLOB` -> `char *` (`C_ORM_TYPE_STRING`); fixed `CHAR(n)` -> `C_ORM_TYPE_CHAR_FIXED`
* **DBCS / UTF-16 Graphic Strings (Db2)**: `GRAPHIC(n)` (`C_ORM_TYPE_GRAPHIC`), `VARGRAPHIC(n)`, `DBCLOB` (`C_ORM_TYPE_VARGRAPHIC`, CCSID `1200`)
* **Binary / Bit Data**: `BLOB` (`C_ORM_TYPE_BLOB`), `BINARY(n)` / `CHAR(n) FOR BIT DATA` (`C_ORM_TYPE_BINARY_FIXED`, CCSID `65535`), `VARBINARY(n)` / `VARCHAR(n) FOR BIT DATA` (`C_ORM_TYPE_VARBINARY`)
* **Dates/Times/Timestamps**: `DATE` (`C_ORM_TYPE_DATE`), `TIME` (`C_ORM_TYPE_TIME`), `TIMESTAMP` (`C_ORM_TYPE_TIMESTAMP`)

## Supported Constraints & Db2 Clauses

The parser extracts standard ANSI constraints as well as IBM Db2 enterprise column modifiers:

* `PRIMARY KEY`: Marks the column as the primary key (inline or table-level composite `PRIMARY KEY (...)`).
* `GENERATED ALWAYS AS IDENTITY (...)` / `GENERATED BY DEFAULT AS IDENTITY (...)`: Recognizes Db2 identity auto-increment columns.
* `FOR BIT DATA` / `FOR SBCS DATA` / `FOR MIXED DATA` and `CCSID EBCDIC | UNICODE | ASCII | <number>`: Preserves binary (`ccsid = 65535`) and mainframe encoding metadata on `c_orm_column_meta_t`.
* `FOREIGN KEY`: Captures the `REFERENCES table(column)` constraint. Currently exposed in metadata array as the target table name string.
* `NOT NULL`: Marks the column as non-nullable. If a column is omitted from this constraint, it is assumed `NULL` by default and is represented as a pointer in the generated C structs (e.g., `int32_t *`).
* `UNIQUE`: Parsed but currently does not affect struct generation; useful for database integrity checks only.
* `DEFAULT`: Values (numbers, strings, `CURRENT_TIMESTAMP`) are parsed but are handled by the database engine upon insertion rather than the C structs themselves.

## Example

```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(255) NOT NULL,
    score FLOAT, /* nullable float */
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
